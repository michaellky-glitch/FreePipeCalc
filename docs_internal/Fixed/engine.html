Calculation Method

How FreePipeCalc calculates friction loss, solves a network, handles equipment and thermal, and sizes domestic water pipework.

Every equation here can be checked by hand. Worked examples show the arithmetic.

1. Scope

This document tells you what the program calculates and how. It does not tell you how to use the interface.

The program calculates:

  • Friction loss in each pipe and fitting.
  • Flow and pressure at every point in a network, including loops.
  • Equipment duty and pipe heat loss in a thermal network.
  • Pipe sizes for domestic water, from fixture units.
Verify before you issue

The results are not approved by any certification body or Authority Having Jurisdiction. A qualified engineer must check them. Velocity pressure is not included, so do not use these results for fire protection design.

Head and pressure

Head is in metres of the working fluid. To convert head to pressure, the program uses the density of that fluid:

ΔP = ρ · g · hf
with g = 9.81 m/s²

If you change the fluid, every pressure changes with it.

3. Pipe friction

Two methods are available. Select the method on the HYDRAULIC tab. The calculation sheet records which method you used.

3.1 Hazen-Williams (default)

Hazen-Williams is an empirical correlation for turbulent water flow. It is the usual method for building services pipework.

Friction head loss hf = 10.67 · L_eff · Q1.852 / ( C1.852 · d4.8704 )

Where the constant 10.67 comes from

The constant is not arbitrary. It follows from the SI velocity form of Hazen-Williams. These are the steps.

  1. Start from the standard SI form, where R is the hydraulic radius and S is the hydraulic gradient hf/L:

    V = 0.849 · C · R0.63 · S0.54

  2. For a full circular pipe, substitute the hydraulic radius and the velocity:

    R = d / 4     V = Q / A = 4Q / (π d²)

  3. Put both into the first equation and collect the terms in d:

    4Q / (π d²) = 0.849 · C · (d/4)0.63 · S0.54

    S0.54 = 41.63 · Q / ( π · 0.849 · C · d2.63 )

  4. Raise both sides to the power 1 / 0.54 = 1.85185. The exponent on d becomes 2.63 × 1.85185 = 4.8704:

    S = [ 41.63 / (π · 0.849) ]1.852 · Q1.852 / ( C1.852 · d4.8704 )

  5. Evaluate the bracket. This is the constant:

    41.63 = 9.5798
    π · 0.849 = 2.6672
    9.5798 / 2.6672 = 3.5917

    3.59171.852 = 10.674

  6. Multiply by the length, because S = hf / L. Use the effective length so that fittings are included:

    hf = 10.67 · L_eff · Q1.852 / ( C1.852 · d4.8704 )

The program derives its constants from the form ASHRAE prints. ASHRAE Ch 22 Eq (6) uses a velocity coefficient of 6.819. Substituting V = 4Q/(π d²) gives:

A = 6.819 · (4/π)1.852 = 10.6663
e = 1.167 + 2 × 1.852 = 4.8710

The two constant sets differ by 0.035% and 0.012%. Both are roundings of the same ASHRAE equation. The program stores the printed form (6.819, 1.852, 1.167) and derives the flow form from it.

How the solver stores it

The solver stores each pipe as a resistance r and an exponent n. The loss is a power law:

hf = r · |Q|n−1 · Q

r = 10.67 · L_eff / ( C1.852 · d4.8704 )     n = 1.852

The loss is written signed in Q, not as |Q|n. This makes it an odd function. Reverse the flow and the loss reverses with it. The solver can then reverse the flow in a loop without any special case.

Worked check — you can do this by hand

100 m of DN50 Schedule 40 pipe. Bore 52.48 mm, C = 120, flow 5 L/s.

r = 10.67 × 100 / (1201.852 × 0.052484.8704) = 258 025.6
hf = 258 025.6 × 0.0051.852 = 14.130 m
ΔP = 998 × 9.81 × 14.130 = 138.3 kPa
V = 0.005 / (π × 0.05248² / 4) = 2.312 m/s

The program's derived constants give 14.1505 m. The two agree to 0.15%. That gap is the rounding in 10.67. The case is asserted in test/engine.test.js.

3.2 Darcy-Weisbach

Darcy-Weisbach applies to any fluid and any flow regime. It uses absolute roughness ε instead of a C value.

Friction head loss hf = f · (L_eff / d) · V² / 2g

Four correlations are available. Swamee-Jain is the default.

CorrelationFormAgreement with Colebrook-White
Colebrook-WhiteImplicitThe reference. Solved by iteration.
Swamee-Jain (default)ExplicitWithin 0.9% over Re 10⁴–10⁷ with ε/d ≤ 10⁻³. Up to 2.8% at the edge of its validity (Re 5000, very rough pipe).
HaalandExplicitWithin 2%. The simplest form.
ChurchillExplicitCovers all flow regimes in one expression.

Across realistic building-services cases (DN25 to DN200, steel and PPR, new and heavily fouled) the four correlations differ by 1.4% or less. The correlation you select has very little effect on the answer.

Laminar flow uses f = 64/Re. In the transitional band the program blends linearly between the laminar and turbulent values. The solver then sees a continuous curve and not a step. Churchill covers all regimes itself and is not blended.

3.3 Which method to use

The method matters more than the correlation

Against Hazen-Williams at C = 120, Darcy-Weisbach with ε = 0.045 mm gives a friction rate 16% to 27% lower.

Neither is wrong. C = 120 represents somewhat aged steel. ε = 0.045 mm represents clean new steel. To compare the two methods, first make them equivalent: use ε ≈ 0.15–0.25 mm, or C ≈ 130–140.

  • Use Hazen-Williams for water at normal building temperatures. This is the default.
  • Use Darcy-Weisbach for other fluids, for glycol mixtures, or where flow is laminar.

3.4 Flow regime

After the solution settles, the program calculates the Reynolds number for each section:

Re = V · d / ν
Reynolds numberRegimeWhat the program does
Re < 2300LaminarWarns. Hazen-Williams does not apply here: it is fitted to turbulent water flow, so in laminar flow it is the wrong equation, not an imprecise one. Use Darcy-Weisbach.
2300 ≤ Re < 4000TransitionalWarns. Friction loss in this band is inherently uncertain.
Re ≥ 4000TurbulentNo warning.

Laminar sections usually appear on oversized pipe at low demand, or on a branch that is nearly shut. You can switch this check off on the HYDRAULIC tab.

3.5 Very low flow

At Q = 0 the slope of the loss curve is zero, because n is less than 2. The solver divides by that slope. It cannot use the curve at the origin.

Below Q_MIN = 1×10⁻⁶ m³/s the program replaces the curve with its tangent at Q_MIN. The tangent passes through the origin. The loss stays continuous, odd, and increasing. The slope stays finite.

4. Fittings

You do not place fittings. The program finds them from the geometry of the drawing. It counts the pipes that meet at each node and the angles between them.

Fitting loss is charged to the downstream pipe.

4.1 Equivalent length — used with Hazen-Williams

Each fitting adds a length of straight pipe. That length is read from a published table. It is keyed on the nominal size. It is not a ratio. Nothing is multiplied by a bore.

Three tables are available. You select one on the HYDRAULIC tab:

TableSourceEditable?
Carrier (default)Carrier Design Handbook, Table 11 — "Fitting Losses in Equivalent Feet of Pipe". Printed in feet, converted to metres (× 0.3048, rounded to 2 dp).No
NFPA 13NFPA 13 (2019), Table 27.2.3.1.1. Printed metric column, stored as printed.No
CustomYour own values. Seeded from whichever table was showing when you switched.Yes

Four fitting types are carried: 90° elbow, 45° elbow, tee branch, and tee run. The table starts at DN25. Below DN25 the value is clamped to the DN25 figure, which overstates the loss. Values between tabulated sizes are interpolated. Values above the largest size are clamped, not extrapolated.

NFPA 13 has no straight-through tee row. A sprinkler calculation does not need one. In the NFPA set, that row comes from the Carrier table. The interface marks it and footnotes it.

Nominal size, not bore

The tables are keyed on the nominal size. Nominal size and bore are different numbers. HDPE "110 mm" is an outside diameter with a 90 mm bore, so a lookup on bore lands two rows away in the table. Bore is used only to calculate velocity.

Published tables are read-only. You cannot edit Carrier or NFPA values. Switch to Custom to change anything. Custom is not a fourth table: it is whatever you typed, seeded from the table that was showing.

Older models saved their fittings as an L/D ratio against the bore. That basis is superseded. The program keeps those values so a saved model still loads, but nothing reads them.

4.2 Resistance coefficients K — used with Darcy-Weisbach

Darcy-Weisbach charges a fitting as a number of velocity heads:

h = K · V² / 2g

Source: 2021 ASHRAE Handbook — Fundamentals, Chapter 22 "Pipe Design", Table 3 (threaded steel fittings) and Table 4 (flanged or welded steel fittings). K changes with size, so each fitting holds a curve against nominal size. Values between tabulated sizes are interpolated. Values outside the tabulated range are clamped, not extrapolated.

Nominal size, not bore

The K tables are keyed on the nominal size. Nominal size and bore are different numbers. HDPE "110 mm" is an outside diameter with a 90 mm bore, so a lookup on bore lands two rows away in the table. Bore is used only to calculate velocity.

ASHRAE records that threaded 90° elbows vary by ±20% above 2 in, and ±40% below 2 in, with the pattern of the fitting. Every K value is editable.

4.3 How a tee is charged

Whether a leg of a tee is a "run" or a "branch" depends on the direction of flow. The direction is only known after the solve. The program therefore:

  1. solves with a geometric estimate — the straightest pair of legs is the run,
  2. reassigns run and branch from the solved flow directions,
  3. solves again.

This settles in one or two passes. If the assignment oscillates, the program keeps the last solution and warns you.

A dividing tee and a combining tee are different fittings. The tables give one run figure and one branch figure. They do not split the two cases. The program therefore charges a combining tee the same as a dividing one. It still records which case a tee is, so you can see it on the calculation sheet.

6. Network solution

6.1 What the solver does

A branched network can be solved by adding losses along each path. A network with a loop cannot. The flow divides between two routes. How it divides is itself part of the answer.

The program uses the Global Gradient Algorithm (Todini–Pilati). This is the method EPANET uses. It solves for two sets of unknowns at the same time:

  • the head H at every junction,
  • the flow Q in every link.

Flow is positive in the direction from the from node to the to node. A negative result means the water flows the other way.

6.2 The equations

Two conditions must hold together.

1 — Continuity, at every junction Σ Qin − Σ Qout = demand at the node
2 — Energy, along every link Hfrom − Hto = hf(Q) = r · |Q|n−1 · Q

The second equation is not linear. The solver linearises it. At the current estimate of Q it takes the slope of the loss curve:

Slope of the loss curve dhf/dQ = n · r · |Q|n−1

It then builds one linear system for all the heads, solves it, and updates every flow. The matrix is a graph Laplacian: symmetric, positive definite, with about four non-zero entries per row. The program factorises it as a skyline LDLᵀ, which suits that shape.

Convergence

The solver repeats until the largest change in flow is small. It reports the number of iterations and the remaining imbalance. Convergence is fast because each step is a Newton step. Near the answer, the error falls quadratically.

Converged is not the same as correct

A solution can converge and still describe a system you did not intend. A ring main that is not actually connected as a ring returns zero flow everywhere. It converges with no errors. The program therefore checks the drawing separately for breaks, islands, and unconnected devices.

6.3 Worked example

This example is small enough to check by hand. The file is examples/GGA example.json.

A source feeds a pump. The pump feeds a ring. Three outflows are spaced around one side of the ring. Each draws 1 L/s and requires 100 kPa. All pipe is DN50, C = 120.

Step 1 — resistance of each pipe

Each pipe gets an r from its effective length. The two pipes next to the tee carry a tee equivalent length, so their L_eff is longer than the 5.00 m drawn:

PipeL drawn (m)L_eff (m)r
P1  N1→N25.008.0520 800.6
P2  N2→N35.006.5216 847.2
P11 N3→N93.505.0212 972.2
P12 N9→N61.501.503 878.1

Step 2 — solve

The solver converges in 3 iterations, to an imbalance of 2×10⁻¹⁶ m³/s.

The ring is symmetrical. You can check the flows without a solver. Total demand is 3 L/s. Both sides have the same resistance, so each carries 1.5 L/s. The middle outflow sits at the meeting point. It takes 0.5 L/s from each side. The solver returns exactly this.

Step 3 — read the result

NodeHead (m)Pressure (kPa)Note

The pump is on automatic sizing. The program raises its head until the worst terminal is exactly satisfied. OF-1 is the hardest to reach. It is furthest along the ring from the pump on both sides. It arrives at exactly 100 kPa, and the other two have a small margin. OF-1 is therefore the index terminal, and it sets the pump duty of 10.762 m.

What to check on your own model

Look at the Critical Path section of the calculation sheet. It lists the sections from the source to the index terminal, and the friction, static and residual pressure along it. The pump duty is the total of that path.

Full verification

Every value in this worked example is independently recomputed and compared against the engine output in Engine Validation.

7. Pumps

7.1 Modes

ModeWhat the program does
AutoIn DESIGN, raises or lowers the head until the worst-served terminal has exactly its required pressure. The duty can come down as well as up.
ManualYou state the flow and the head. The program does not change them.
CurveYou give H against Q, from the manufacturer. In SIMULATE the operating point is read from this curve.

A safety margin, as a percentage, can be added to the calculated duty.

7.2 The curve equation

A pump curve is stored as a falling power law:

Pump head H = H0 − a · Qb

where H is in metres, Q in m³/s, H0 is the shutoff head (head at zero flow), and a and b shape the curve. The solver uses this form because its derivative is simple:

Slope dH/dQ = −b · a · Qb−1

This is the slope the Newton iteration uses. For the default exponent b = 2 this simplifies to dH/dQ = −2aQ.

Generated curve — Auto and Manual sizing

Auto and Manual sizing generate a curve from the design duty. The program builds three points from the duty:

  • shutoff — the shutoff head at zero flow. Default 140% of duty head,
  • duty — the design point itself,
  • runout — beyond the duty. Default 150% of duty flow at 65% of duty head.

The three percentages are editable on SETTINGS. They are a representative shape, not manufacturer data. A real curve differs. Use Curve sizing when you have one.

Curve from pasted manufacturer data

Paste Q, H points from the manufacturer. The program fits H = H0 − a·Qb. It sweeps b over a plausible range (1.2 to 3.0). At each candidate it solves H0 and a by linear least squares. The best b is refined by bisection. R² and maximum deviation are reported so the engineer can judge the fit.

Curve from three stated duties — the TOOLS generator

The TOOLS tab has a curve generator. You state three duties: shutoff, design, and runout. The program fits an exact quadratic through them:

h(q) = a + b · q + c · q²

It uses Newton's divided differences. This is an interpolation. It passes through all three points exactly. The generator warns if the curve does not look like a pump: shutoff head not positive, or head rising with flow.

What was removed

The single-point curve is gone

An earlier build generated a curve from the EPANET single-point assumption: shutoff at 133% of duty head, runout at 200% of duty flow. It was removed. It is one manufacturer-agnostic guess handed to the engineer as though it were an answer, and it cannot reach the shapes that are actually specified — an NFPA 20 fire pump allows shutoff up to 140% and requires 65% of rated head at 150% of rated flow. The function survives in the code only as a test fixture. It is not reachable from the interface.

A curve is now mandatory in SIMULATE. A running pump without one used to fall back silently to a constant head. That answers a different question: flow stops responding to the system. The program now raises an error instead.

7.3 Affinity laws — variable speed

A pump running at a fraction s of rated speed follows the affinity laws:

Affinity scaling Q ∝ N     H ∝ N²

Hs(Q) = s² · H(Q / s)

Substituting into the stored curve produces a new curve in the same form:

H0' = s² · H0
a' = a · s(2−b)
b' = b

At b = 2 (the default) the exponent term is s⁰ = 1, so a is unchanged and the curve simply drops. This is the standard VSD family. The duty point rides the affinity parabola to (s·Qd, s²·Hd).

Efficiency is not scaled

The app does not carry a power curve, so there is nothing to be wrong about. The affinity laws are exact for the ideal machine and are the basis of every published VSD family.

7.4 How the solver uses the pump

The energy equation along a pump link is:

Hfrom − Hto = −Hpump(Q)

The pump adds head. The term is negative because flow goes from low head to high head across the pump. For a fixed-head pump, Hpump is constant. For a curve, the solver finds the operating point where the curve meets the system. It does this for the whole network at once. No separate system-curve intersection is needed or wanted. With several pumps and rings there is no single scalar system curve to intersect.

The derivative dH/dQ vanishes at shutoff for b > 1. This is the same singularity a fixed-head pump has. The slope is floored at a minimum (1.0 m/(m³/s)) to keep the Newton step finite.

Automatic sizing (DESIGN)

In DESIGN, automatic sizing adjusts the pump head until the worst-served terminal has exactly its required pressure. The head can come down as well as up. A linear droop is imposed on the resulting head — H = Hd + k(Qref − Q) — so the sizer can always reach its target. The slope k defaults to Hd/Qref.

7.5 Control

A pump can follow a sensor. Link the pump to a pressure, flow or temperature sensor and give the sensor a setpoint. In SIMULATE the program adjusts the pump speed until the sensor reads its setpoint. If the pump reaches a limit before it reaches the setpoint, the program says so.

Control applies in SIMULATE only

In DESIGN the demands set the flow, and automatic sizing sets the duty. A controller cannot also set them: two controllers on one actuator have no single answer. In SIMULATE the flow is free to respond, so the controller has something to act on.

8. Equipment

Equipment is any in-line device that adds or removes heat, or drops pressure without a thermal effect. Three types share one hydraulic resistance model. They differ in their thermal behaviour.

8.1 Hydraulic resistance

Every piece of equipment carries a pressure drop rated at a design flow. The solver converts this to a quadratic resistance:

Equipment resistance r = ΔPrated / (ρ · g · Qrated²)

hloss = r · Q²

where ΔPrated is in Pa, Qrated in m³/s, and ρ is the fluid density. The exponent is always 2 (Darcy-like), regardless of the pipe friction method.

An integrated control valve (ICV) on a coil adds its own globe-valve resistance in series on the same link:

rtotal = requip + rvalve(Kv,ICV, opening)

Equipment that is switched off is omitted from the network entirely — a genuine break, not a bypass.

8.2 Thermal behaviour

Temperature is transported by the water. The thermal solve runs after the hydraulic solve and reads its flows. Nothing here feeds back into the hydraulics. Fluid properties are fixed at one temperature. The three thermal phenomena are:

Mixing at a junction

Rule of mixtures, mass-weighted:

Tmix = Σ(ṁi · Ti) / Σ(ṁi)

Weighted by mass flow rather than volume because it is energy that mixes; with one fluid and constant Cp the Cp cancels and this is exact.

Pipe heat loss or gain

For constant ambient temperature and a constant overall heat-loss coefficient, the outlet temperature has a closed form:

Pipe outlet temperature Tout = Tamb + (Tin − Tamb) · exp(−U' · L / (ṁ · Cp))

where U' is the loss per metre per kelvin, from the insulation geometry. This is exponential, not linear. The driving difference shrinks as the water approaches ambient. On a long run at low flow, a linear model can walk the temperature straight past ambient and out the other side. This form cannot. It approaches ambient and stops.

U' is computed from the insulation and surface film:

R' = ln(ro/ri) / (2πk) + 1 / (2π · ro · ho)
U' = 1 / R'

where ri is the pipe outside radius. Insulation sits on the pipe, not in the bore. ro = ri + insulation thickness. k is the insulation conductivity. ho is the outside surface coefficient (default 8 W/(m²·K)). Setting ho = 0 makes the pipe adiabatic.

Two thermal types, distinguished by what you know at design:

TypeYou stateTemperature follows?Limits

(AHU, FCU, plate HX)		Thermal load (duty, W)Yes — temperature follows from Q = duty / (ṁ · Cp)Design ΔT (ΔTmax), temperature limit (Tlimit)

Sign is inferred, never selected. A setpoint below the inlet is cooling. A chilled-water coil is positive — the water gets warmer — even though the room is being cooled.

Source / sink — leaving temperature

The machine holds its leaving temperature by modulating duty. The duty it needs at the current flow and inlet is:

Required duty Qneed = ṁ · Cp · (Tset − Tin)

This is signed. It is negative for cooling (Tset < Tin) and positive for heating. The machine is limited by:

  • Capacity (qmax): |Qneed| ≤ |qmax|. If signed capacity and signed duty have opposite signs, the machine is working the wrong way and delivers nothing.
  • Temperature limit (Tlimit): only on heat exchangers, not sources. A tower cannot cool below wet bulb, but whether a leaving temperature is physically achievable is a judgement the engineer makes.

The outlet is: Tout = Tin + min(|Qneed|, |qmax|) / (ṁ · Cp), in the correct direction.

Heat exchanger — stated load

The duty is the stated quantity. Temperature follows:

Exchanger outlet temperature Tout = Tin + duty / (ṁ · Cp)

Limited by:

  • Design ΔT (ΔTmax): |Tout − Tin| ≤ ΔTmax. If the actual ΔT would exceed the design value, the duty is capped.
  • Temperature limit (Tlimit): the machine cannot take the fluid past this physical limit. The limit is applied on whichever side the machine works from.

There is no capacity limit. The duty is the stated quantity.

Adiabatic

A filter, strainer, or flow meter: real pipework with a real pressure drop and no thermal properties. The water leaves as it arrived. This is a type rather than a zero duty. "No thermal behaviour" and "a duty that happens to be zero" are different statements. Only the first should hide the thermal fields.

Load percentage

A loadPct scales what the machine is asked to do without touching the design figure. This is a way of asking "what if this coil were at 40%?" without losing the number the machine is scheduled at. If absent, the design figure is the answer.

8.4 The thermal solve is exact

Every relation is affine in temperature:

PhenomenonRelationForm
MixingT = Σ(ṁiTi) / ΣṁiLinear
Pipe lossTout = Tamb + (Tin − Tamb) · e−xAffine, e−x fixed
EquipmentTout = Tin + ΔT  or  Tin + Q/CAffine

The whole network is one linear system A·T = b. It is solved exactly in one pass. Equipment clamps are piecewise linear. Which branch applies depends on the inlet temperature, which is what the solve produces. The active set is frozen, the system is solved, the set is re-computed from the answer, and it repeats until nothing changes — typically two or three passes.

9. Outflows

An outflow is a demand node. Water leaves the system there. The solver treats it differently depending on the mode.

9.1 DESIGN — stated flow

In DESIGN, each outflow states a required flow Qd and a required pressure ΔPd. The solver treats the flow as a fixed demand at the node:

Node continuity Σ Qin − Σ Qout = Qd

The required pressure sets the pump duty — it is not used in the solve itself, only in sizing the pump to satisfy the worst terminal.

9.2 SIMULATION — pressure-dependent terminal

In SIMULATION, the outflow becomes a short link to a virtual discharge node. The discharge node is pinned at the outflow's own elevation (zero gauge). The link carries a quadratic resistance derived from the design point:

Terminal resistance K = Qd / √(ΔPd)

r = ΔPd / (ρ · g · Qd²)

Flow through that link is what the terminal actually delivers:

Q = K · √P     or equivalently     Q = √(P / r) / √(ρg)

A fixture therefore discharges more water where the pressure is high, and less where it is short. This is correct behaviour and it is what you use the simulation to find.

Required pressure must be non-zero

An outflow with zero required pressure has no characteristic K = Q/√P and cannot be simulated. The smallest meaningful value is 100 Pa (0.1 kPa).

9.3 Domestic water fixtures

In the plumbing discipline, an outflow is a fixture. Its design flow comes from fixture units to IPC Appendix E (see §13). In SIMULATION it behaves identically to a generic outflow: Q = K·√P, with K derived from the fixture's undiversified flow and required pressure.

10. Sources

A source is a boundary condition: it states the pressure (or head) the water arrives at. In an open system a source is where water enters the network.

10.1 Hydraulic

The source sets a fixed head at its node:

Hsource = z + Psource / (ρ · g)

where z is the node elevation and Psource is the gauge pressure at the connection point (e.g. mains pressure). The solver uses this as a known head — the same role a reservoir plays in EPANET.

An off-screen or atmospheric source at zero gauge pressure sets H = z.

10.2 Thermal

A source introduces water at a stated temperature. It is a stream, not a hard pin. It mixes with whatever arrives at the node, carrying only the mass it actually introduces.

Source mixing Tnode = (ṁpipes · Tmixed + ṁsource · Tsource) / (ṁpipes + ṁsource)

On a branch-end source, the source brings in all the flow. The node is at the source temperature and nothing changes. Teed into a live main, only the make-up mixes. The rest of the water flows past.

A source moving no water at all still states a temperature. It is a stated boundary that happens to be idle, not a dead leg guessing from its neighbour.

Sealed circuits have no source

A closed loop (chilled-water ring, heating circuit) has no source. One node is pinned instead. The pin sits at the outlet of whatever removes the most heat — the plant. Its leaving temperature is the number an engineer quotes as the flow temperature. If the temperature field has no unique solution (an adiabatic loop with nothing tying it to ambient), the program reports an error.

11. Valves

Valves are sized by flow coefficient rather than equivalent length. The solver charges them as a quadratic resistance: h = r·Q².

11.1 Kv and Cv

Flow coefficient Kv = flow in m³/h that produces a 1 bar drop across the valve
Cv = flow in US gpm that produces a 1 psi drop. Cv ≈ 1.156 · Kv.

Pressure drop follows the square law:

ΔP [bar] = (Q [m³/h] / Kv)²

Converted to SI head-basis resistance for h = r·|Q|·Q, Q in m³/s:

Valve resistance r = 105 · 3600² / (Kv² · ρ · g)

A shut valve uses r = 1012. This is high enough to pass no meaningful flow, but finite so the solver matrix stays non-singular.

11.4 Check valve

A check valve blocks reverse flow. Direction is only known after the solve. This uses a two-pass approach:

  1. Solve with the geometric estimate of flow direction.
  2. If the upstream head is lower than the downstream head, the valve is holding shut (r = 1012).
  3. Solve again.

The test is on head, not flow. Testing flow oscillates forever. Shut the valve because flow was negative. The next pass reports ~zero flow, which is not negative, so it reopens. The adverse head difference is stable because it persists while the valve is held shut.

12. Thermal summary

The thermal module is a single linear system. It is solved in one pass, plus two or three active-set iterations for equipment clamps. The three phenomena — mixing, pipe heat loss, and equipment duty — are all affine in temperature.

12.1 Energy balance

At steady state, what goes in must come out:

Σ qequip + Σ qpipe + qsource − qboundary = 0

For a closed circuit the boundary term is zero. No water enters or leaves. For an open circuit, water carries energy across the boundary. The residual is reported separately from the link duties.

12.2 Reference temperature

Something must be known. Without it, every temperature floats. In priority order:

  1. A source states the temperature of the water it introduces. This is stream mixing, not a hard pin.
  2. A pinned datum at the outlet of the equipment moving the most heat. This is used only when no source introduces water and the loop is adiabatic (no pipe heat exchange). The pin holds its stated temperature whatever arrives, and the energy it absorbs is reported as a heat imbalance.
  3. If neither is needed (the loop is coupled to ambient through pipe heat loss), the system finds its own level against ambient.

12.3 Pumps and valves

Pumps and valves pass temperature straight through. A pump does put shaft work into the water. At typical duties that is hundredths of a kelvin. Stating it would imply a precision the rest of the thermal module does not have.

13. Domestic water

A domestic water file is a separate discipline. It is sized from fixture units, to IPC 2018 Appendix E. The network solver is not used to size it.

13.1 From fixtures to a design flow

  1. Each fixture carries a number of cold fixture units, from IPC Table E103.3(2). A fixture unit is a measure of load, not a flow.

  2. The program adds the fixture units of everything downstream of a pipe.

  3. It converts that total to a probable flow through the demand curve, IPC Table E103.3(3). This curve is sub-additive. 100 fixture units draw far less than 100 times the flow of one. The fixtures do not all run at once.

  4. Any generic outflow downstream is added on top, without diversity. A continuous draw — a hose, a process supply — is not a fixture unit and does not diversify.

Design flow in a pipe Q = fuToFlow( Σ fixture units downstream ) + Σ generic flow downstream
Domestic water does not balance, and should not

Because the demand curve is sub-additive, the flow in a main is less than the total of the branches it feeds. This is correct. It is diversity, not an error in continuity.

13.2 The network must be a tree

"Downstream" is only defined when there is one path from the source to each fixture. The program therefore requires a tree: one source, no loops. If it finds a loop, more than one source, or no source, it reports the problem instead of estimating an answer.

13.3 Fixture flow and pressure

Each fixture also carries an undiversified flow and a required flow pressure, from IPC Table 604.3. These are the values at the outlet when that fixture runs on its own. They are used to size a booster and to simulate.

Where a fixture is not listed in Table 604.3, the value is estimated from similar fixtures. Estimated values are shown in red on the HYDRAULIC tab. All values are editable.

13.4 Booster duty

A booster must satisfy the most remote fixture while that fixture is running, at its full outlet flow. Everything behind it is still a population, and still diversifies.

Duty flow Q = undiversified flow of the index fixture
  + fuToFlow( total fixture units − fixture units of the index fixture )
  + generic flow served

The index fixture is the one with the least margin between the pressure delivered to it and the pressure it requires. This is the same definition the Critical Path uses, so the calculation sheet and the pump agree.

The duty head is the head that brings the index fixture to exactly its required pressure. The forward pass is linear in pump head, so this is exact in one pass. The duty comes down as readily as it goes up.

13.5 Simulation

DESIGN sizes the pipe. SIMULATE tells you what the system delivers.

In SIMULATE each fixture that is switched On becomes a pressure-dependent terminal. It behaves exactly as a hydronic terminal does. Its K comes from its own design point:

Fixture characteristic Q = K · √P     K = Qdesign / √Pdesign

A fixture therefore discharges more water where the pressure is high, and less where it is short. This is correct behaviour. This is what you use the simulation to find.

Worked check

One source, one pipe, one lavatory. Double the supply pressure and the draw increases by √2, as the law requires.

300 kPa → 0.1177 L/s
600 kPa → 0.1665 L/s

0.1665 / 0.1177 = 1.4142    (√2 = 1.4142)

You decide which fixtures are open, with the On/Off switch on each outflow. A multiple selection can be switched together. The load case is yours to choose. The program does not choose it for you.

High static pressure

A fixed-speed booster develops more head as the draw falls. The highest pressure in a domestic system is therefore at its quietest, not its busiest. The program warns above a static pressure limit, which defaults to 552 kPa (80 psi) and is editable on the HYDRAULIC tab.

15. Limits of the method

These are known. Read them before you rely on a result.

1 — Tee losses are approximate

Straight-pipe friction is validated. Tee losses are not.

A tee is charged as a "run" or a "branch" from its geometry alone. Real tee loss depends on whether the flow divides or combines, and above all on the ratio of branch flow to combined flow. K varies over that ratio by more than a factor of ten. One flat value cannot represent it.

The tables give one run figure and one branch figure. They do not split dividing from combining. The program charges both the same. This is a faithful reading of the source, not an invented simplification.

The effect is small on a network whose losses are mostly straight pipe. It is larger on short, heavily branched pipework.

2 — The tables start at DN25

See section 4.1. A pipe below DN25 clamps to the DN25 figure. This overstates the loss, and the interface does not warn. Check small-bore branches by hand.

3 — NFPA has no straight-through tee

See section 4.1. In the NFPA set that row comes from Carrier. The interface marks it.

4 — Temperature does not drive fluid properties

Density and viscosity are entered, not calculated from the temperature. A circuit running at 6 °C with 20 °C properties entered will use the 20 °C properties.

5 — Velocity pressure is neglected

Appropriate for plumbing and hydronic work. Not appropriate for fire protection design.
